The shared cluster problem

CRD conflicts

Multiple teams deploying incompatible custom resources crash the cluster or interfere with each other.

GPU starvation

Long-running jobs and experiments compete for GPUs. Priority queuing isn't enough for isolated experiments.

Weak isolation

Namespaces don't prevent node access, CRD collisions, or etcd bloat. Workloads aren't truly isolated.

How Ghostcluster works

Lightweight isolation at scale

Ghostcluster creates one ephemeral vCluster per workload. Each cluster is a complete, isolated Kubernetes environment with its own API server, controller manager, and scheduler.

All clusters share the underlying physical nodes and GPU resources. When the TTL expires, the cluster self-destructs—no manual cleanup needed.

No CRD conflicts. No GPU starvation. No namespace workarounds.

Why vCluster?

vCluster is battle-tested in production at scale. It provides real Kubernetes isolation at a fraction of the cost and complexity of full cluster-per-workload deployments.

Lightweight

vCluster runs inside a single pod. Spawn dozens or hundreds without infra overhead. Share GPUs efficiently across clusters.

True isolation

Separate API server, etcd, and scheduler per vCluster. CRDs, RBAC, and resources are fully scoped. Safe for untrusted workloads.

Standard Kubernetes

Full Kubernetes API compatibility. No custom tools, no vendor lock-in. Deploy helm charts, operators, and workloads as-is.

Production-ready

Used by enterprises and cloud platforms. Proven at scale with SLAs and security hardening.

Key capabilities

vCluster-based isolation

Full Kubernetes isolation without the overhead of separate etcd clusters or complex scheduling.

TTL-based auto-cleanup

Set a lifetime when you create the cluster. No dangling resources, no manual teardown.

GPU quotas & passthrough

Request specific GPU counts. Isolation rules prevent other clusters from using your GPUs.

Network & storage isolation

Each vCluster gets its own virtual network. Storage is scoped within the cluster instance.

CLI-first workflow

Fast iteration. No UI, no cloud console. Build on what works: ghostctl and kubectl.
